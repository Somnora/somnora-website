The project

What it does

Today In Time treats historical material as an editorial product rather than an infinite scraped feed. Each event has a stable record contract, publishable status, tone, category, narrative fields, and one or more sources. The app can present an uplifting, balanced, or more unflinching selection without hiding where the story came from.

The runtime is intentionally simple and offline-friendly. A bundled corpus is decoded into a stable HistoricalEvent model, then reused by the feed, detail, Explore, Saved, and Quiz experiences. A smaller generated slice feeds the widget, and CI prevents that slice from drifting away from the main corpus.

System architecture

How the system moves

The editorial corpus is validated before it reaches Xcode. At runtime, one loader and one normalized model insulate every view from the source JSON shape, while local stores preserve user choices without requiring an account.

Editorial record to daily reading

  1. 01 · Editorial

    Sourced event records

    Each record carries date, narrative, category, tone, status, and provenance.

  2. 02 · Data gate

    Validation and widget slice

    Scripts reject invalid records and regenerate the smaller one-per-day widget corpus.

  3. 03 · Bundle

    Local JSON resources

    The validated main corpus and widget slice ship inside their respective targets.

  4. 04 · Model

    DataLoader and HistoricalEvent

    Fallback fields, aliases, and publishability rules become one stable app model.

  5. 05 · Experience

    Feed, detail, Explore, Quiz

    SwiftUI surfaces select stories by date, tone, category, and user intent.

  6. 06 · Personal state

    Saved, feedback, widget

    Local stores remember reading choices and share the daily record with the widget.

The source corpus is an input artifact, not a live content API. That keeps reading fast and predictable, while CI holds the app and widget to the same editorial contract.
